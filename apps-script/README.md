# Бэкенд на Google Apps Script — инструкция по подключению

Сайт хранит записи, окна приёма, визиты и финансы в Google Таблице «Учет».
Связь сайта с таблицей делает небольшой скрипт `Code.gs`. Ниже — всё по шагам,
без программирования.

> Пока скрипт не подключён, сайт работает в **демо-режиме** на выдуманных данных
> (вход в админку — пароль `demo`). Это нормально.

---

## 1. Вставить скрипт в таблицу

1. Откройте таблицу «Учет» в Google Таблицах.
2. Меню **Расширения → Apps Script**. Откроется редактор скриптов.
3. Слева будет файл `Код.gs` (или `Code.gs`). Выделите всё, что в нём есть, и удалите.
4. Откройте файл `apps-script/Code.gs` из этого репозитория, скопируйте **весь** текст
   и вставьте в редактор.
5. Добавьте второй файл: **«+» рядом с «Файлы» → «Скрипт»**, назовите `Bot` и вставьте
   в него весь текст `apps-script/Bot.gs` (Telegram-бот). Он нужен, даже если бот вы
   пока не подключаете: `Code.gs` пользуется его функциями.
6. Нажмите значок дискеты **«Сохранить проект»** (или Ctrl+S / Cmd+S).
   Проект можно назвать, например, «Сайт стоматологии».

## 2. Создать новые листы — `setup()`

1. Вверху редактора, рядом с кнопкой **«Выполнить»**, есть выпадающий список функций.
   Выберите **`setup`**.
2. Нажмите **«Выполнить»**.
3. Google попросит разрешения: **«Проверить разрешения» → выберите свой аккаунт →
   «Дополнительные настройки» → «Перейти на страницу проекта (небезопасно)» → «Разрешить»**.
   Предупреждение «небезопасно» появляется для любого личного скрипта — это ваш
   собственный код, всё в порядке.
4. В таблице появятся листы:
   - **«Окна»** — сюда вы вписываете, когда врач готов принимать;
   - **«Онлайн-запись»** — сюда сайт и бот складывают заявки пациентов
     (последняя колонка `chat_id` — Telegram пациента, если он записался через бота);
   - **«Планы»** — планы лечения из Telegram-бота.

`setup()` можно запускать повторно: существующие листы он не пересоздаёт,
только добавляет недостающее.

Старые листы («Пациенты», «Визиты», «Расходы», «Прайс», «Запись») скрипт не меняет —
только дописывает новые строки в конец, когда вы добавляете что-то через админку.

## 3. Задать пароль персонала (и Telegram по желанию)

Пароль **не хранится в коде** — только в настройках скрипта.

1. В редакторе слева нажмите на шестерёнку **«Настройки проекта»**.
2. Прокрутите вниз до раздела **«Свойства скрипта»** → **«Добавить свойство скрипта»**.
3. Добавьте:

| Свойство | Значение | Обязательно |
|---|---|---|
| `STAFF_PASSWORD` | пароль для входа в админку (придумайте длинный, 12+ символов) | да |
| `TELEGRAM_BOT_TOKEN` | токен Telegram-бота (см. раздел «Telegram-бот») | нет |
| `SITE_URL` | адрес сайта, например `https://имя.github.io/репозиторий` | для бота |
| `TELEGRAM_CHAT_ID` | запасной чат для уведомлений, пока никто не вошёл в бота | нет |

4. Нажмите **«Сохранить свойства скрипта»**.

Настройка Telegram-бота описана ниже, в разделе **«Telegram-бот»** — сделайте это после
публикации веб-приложения (шаг 4).

## 4. Опубликовать как веб-приложение

1. Вверху справа **«Развернуть» → «Новое развёртывание»**.
2. Нажмите шестерёнку рядом с «Выберите тип» → **«Веб-приложение»**.
3. Заполните:
   - Описание: любое, например «v1»;
   - **Выполнять от имени: Я** (ваш аккаунт);
   - **У кого есть доступ: Все**.
4. **«Развернуть»** → при необходимости снова выдайте разрешения.
5. Скопируйте **URL веб-приложения** — он оканчивается на `/exec`.
6. Откройте в репозитории `js/config.js` и вставьте адрес:

```js
API_URL: 'https://script.google.com/macros/s/XXXXXXXX/exec',
```

7. Сохраните и опубликуйте сайт (закоммитьте изменения в GitHub). Демо-режим выключится.

**Проверка:** откройте в браузере `ВАШ_URL?action=services` — должен показаться прайс
в виде текста `{"ok":true,"data":[...]}`.

## 5. Если меняли код скрипта

После любого изменения `Code.gs` сайт продолжит работать на **старой** версии, пока вы
не обновите развёртывание:

**«Развернуть» → «Управление развёртываниями» → карандаш «Изменить» → Версия: «Новая версия» → «Развернуть».**

Так адрес `/exec` **не меняется**, и править `config.js` не нужно.
(Если вместо этого сделать «Новое развёртывание», появится новый адрес.)

## Как заполнять лист «Окна»

Одна строка = одно время, на которое пациент может записаться.

| Дата | Время | Врач | Длительность (мин) | Комментарий |
|---|---|---|---|---|
| 07.11.2026 | 15:00 | | 60 | |
| 07.11.2026 | 16:00 | | 60 | |
| 07.11.2026 | 17:30 | | 90 | |
| 08.11.2026 | 10:30 | | 60 | только консультации |

- **Дата** — обычная дата таблицы или текст `07.11.2026` / `07.11.26`.
- **Время** — `15:00` (часы:минуты). Колонка заранее сделана текстовой, чтобы время не
  превращалось в число.
- **Врач** — можно **оставлять пустым**: Юлия и Тихон принимают вместе, окно общее для
  команды, и пациент на сайте врача не выбирает. (Если всё же впишете `Юля` или `Тиша`,
  окно тоже появится на сайте; два одинаковых времени в один день покажутся один раз.)
- Длительность и комментарий — для вас, на сайте не показываются.

Окна удобно добавлять пачкой через админку: раздел **«Окна приёма»** — укажите дату,
начало, конец и шаг, и все слоты создадутся сами (колонка «Врач» останется пустой).

Время считается занятым, если на эту дату и время уже есть запись в «Онлайн-запись»
(в колонке «Врач» у таких записей стоит `Юля и Тиша`) со статусом не `отменена`.
Сайт показывает пациенту только **свободные** окна на ближайшие 14 дней и не показывает
те, что начинаются меньше чем через час. Чтобы закрыть окно — просто удалите строку
из «Окна».

## Статусы онлайн-записи

Лист «Онлайн-запись», колонка **«Статус»** (менять удобно в админке):

| Статус | Что значит | Время занято? |
|---|---|---|
| `новая` | пациент записался на сайте, ещё не подтвердили | да |
| `подтверждена` | связались с пациентом, он придёт | да |
| `отменена` | запись отменена — время снова появится на сайте | **нет** |
| `пришёл` | пациент был на приёме | да |

Совет: после приёма добавьте визит в разделе «Визиты» — так он попадёт в общую выручку.

## Telegram-бот

Бот работает в том же проекте Apps Script (файл `Bot.gs`). Он умеет:

- **для врачей:** открывать рабочие дни кнопками (утро 9–14, вечер 15–21 или весь день —
  окна по часу создаются сами), закрывать дни, смотреть и подтверждать/отменять записи,
  получать уведомления о каждой новой записи, назначать пациенту **план лечения**
  и искать карточку пациента;
- **для пациентов:** записаться (дата → время → имя → телефон), посмотреть свой план
  лечения и свои записи, отменить запись, узнать адрес. Накануне приёма бот присылает
  напоминание, а за неделю до срока по плану — «не забудьте записаться».

Часы утра и вечера меняются в начале `Bot.gs` (константы `MORNING` и `EVENING`).

### Подключение по шагам

1. **Создать бота.** В Telegram откройте **@BotFather** → `/newbot` → придумайте имя
   (например, «Стоматологи Юлия и Тихон») и username — латиницей, на конце `bot`
   (например, `yulia_tikhon_dent_bot`). BotFather пришлёт **токен** вида `1234567890:AAH...`.
2. **Свойства скрипта** (Настройки проекта → Свойства скрипта):
   - `TELEGRAM_BOT_TOKEN` — токен из шага 1;
   - `SITE_URL` — адрес сайта на GitHub Pages, без `/` на конце;
   - `STAFF_PASSWORD` — уже есть, тот же пароль, что для админки.

   `TG_WEBHOOK_SECRET`, `STAFF_CHAT_IDS` и `BOT_USERNAME` бот создаст сам — их вписывать
   не нужно.
3. **Обновить веб-приложение:** «Развернуть» → «Управление развёртываниями» → карандаш →
   Версия: **«Новая версия»** → «Развернуть». (Если веб-приложение ещё не публиковали —
   сделайте шаг 4 из начала инструкции.)
4. **Запустить по очереди** (выбрать функцию в списке → «Выполнить»):
   1. `setup` — создаст лист «Планы» и колонку `chat_id`;
   2. `setWebhook` — подключит бота к веб-приложению. Если в журнале ошибка
      «Не удалось узнать адрес /exec», добавьте свойство `WEBAPP_URL` с адресом
      веб-приложения (оканчивается на `/exec`) и запустите снова;
   3. `setBotCommands` — команды в меню бота;
   4. `installTriggers` — ежедневные напоминания около 12:00 по Москве.

   При первом запуске Google снова попросит разрешения (теперь — на отправку запросов
   во внешние сервисы и на триггеры) — разрешите.
5. **Врачам:** каждый открывает бота и пишет `/login пароль`. Бот сразу удалит это
   сообщение и покажет меню врача. Уведомления о новых записях приходят всем вошедшим.
   Выйти — `/logout`.

### Как проверить, что всё работает

- Напишите боту `/start` — должно прийти приветствие с меню. Если тишина — запустите
  функцию `webhookInfo` и посмотрите журнал: `url` должен оканчиваться на `?tg=…`,
  а в `last_error_message` не должно быть свежих ошибок.
- Врач: «Рабочие дни» → дата → «Вечер» → в листе «Окна» появятся строки 15:00…20:00.
- С другого аккаунта (как пациент): «Записаться» → пройти шаги → у врачей придёт
  уведомление, в «Онлайн-запись» появится строка с `chat_id`.
- Иногда в `webhookInfo` видна ошибка `302 Moved Temporarily` — это особенность Google:
  ответ веб-приложения идёт через переадресацию. Бот при этом работает, а повторные
  доставки одного и того же сообщения он распознаёт и игнорирует.

### План лечения

Врач: «План лечения» → найти пациента (или «Новый пациент») → услуга из прайса или
«Другое» → комментарий (например, «кариес 2.6, контактный») → срок. Бот сохранит план
в лист «Планы» и пришлёт две ссылки — в Telegram и на сайт. Перешлите пациенту любую.
Если пациент уже писал боту раньше, план придёт ему сам.

Статусы плана: `активен` → `записан` (пациент записался по плану) → `выполнен`
(кнопка в карточке пациента или вручную в таблице).

### Ограничения

- **Бот может написать пациенту только после того, как тот сам нажал «Старт»** (`/start`)
  в боте — так устроен Telegram. Поэтому пациентам с сайта напоминания не приходят,
  пока они не откроют бота (например, по ссылке-плану).
- Бот работает только в личных сообщениях, в группах он молчит.
- Apps Script отвечает за 1–3 секунды — это нормально для бесплатного сервера.

## Безопасность — важно

- **Не публикуйте ссылку `/exec` вместе с паролем** (в чатах, сторис, README). Сама ссылка
  есть в `config.js` и видна всем — это нормально: без пароля через неё можно только
  посмотреть прайс и свободное время и записаться.
- **Пароль храните только в «Свойствах скрипта».** Никогда не вписывайте его в `Code.gs`,
  `config.js` или другие файлы репозитория — репозиторий публичный.
- После 5 неверных паролей подряд вход блокируется на 10 минут для всех.
- Ссылку вебхука бота (`…/exec?tg=…`) никому не показывайте: секрет `tg` защищает бота
  от поддельных сообщений. Если он утёк — удалите свойство `TG_WEBHOOK_SECRET` и снова
  запустите `setWebhook`.
- Вход в админку действует 12 часов. Чтобы выкинуть всех из админки (например, после смены
  пароля), в редакторе выберите функцию **`logoutEverywhere`** и нажмите «Выполнить».
- Если в имени или комментарии пациента текст начинается с `=`, `+`, `-` или `@`,
  скрипт ставит перед ним апостроф — так в таблицу нельзя «подсунуть» формулу.
